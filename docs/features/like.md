# 機能定義：いいね（F-05）

## 概要

投稿に対していいねを追加・取消できる機能。
第三者もいいね可能で、1ユーザーにつき1投稿1回まで。
件数はタイムラインおよび投稿詳細画面に表示される。

> **実装済み**: いいね追加・取消（楽観的更新）。

---

## いいね追加

### 条件

- ログイン済みユーザーのみ実行可能
- 同一ユーザーが同一投稿に複数回いいねすることはできない（DB の UNIQUE 制約で保証）

### 処理フロー

1. タイムライン または 投稿詳細画面のいいねアイコンをクリック
2. バックエンドAPIへいいね追加リクエスト送信
3. `likes` テーブルへ `(post_id, user_id)` を保存
4. いいねアイコンの色を変更（未いいね → いいね済み）
5. いいね件数を +1 して即時反映（楽観的更新: API 完了前に UI を先に変更し、失敗時はロールバック）

---

## いいね取消

### 条件

- いいね済みの投稿のみ取消可能

### 処理フロー

1. いいね済みのアイコンをクリック
2. バックエンドAPIへいいね取消リクエスト送信
3. `likes` テーブルから該当レコードを物理削除
4. いいねアイコンの色を元に戻す（いいね済み → 未いいね）
5. いいね件数を -1 して即時反映

---

## 表示仕様

| 状態 | アイコン表示 |
|------|------------|
| 未いいね | ハートアイコン（アウトライン）＋件数 |
| いいね済み | ハートアイコン（塗りつぶし・赤）＋件数 |

---

## いいねデータ属性

| カラム | 型 | 必須 | 説明 |
|-------|---|------|------|
| id | BIGINT | ○ | 主キー（AUTO_INCREMENT） |
| post_id | BIGINT | ○ | 対象投稿（FK: posts.id） |
| user_id | BIGINT | ○ | いいねしたユーザー（FK: users.id） |
| created_at | TIMESTAMP | ○ | 作成日時（サーバー自動設定） |

**インデックス**
- UNIQUE: `(post_id, user_id)` — 重複いいねをDB層で防止
- INDEX: `post_id` — 投稿ごとのいいね件数取得を高速化

---

## API仕様

| Method | Path | 認証 | リクエスト | レスポンス |
|--------|------|------|----------|---------|
| POST | `/api/likes` | JWT必須 | `{ postId: number }` | 204 No Content |
| DELETE | `/api/likes/{postId}` | JWT必須 | — | 204 No Content |

- 既にいいね済みの状態で追加しようとすると 409 Conflict を返す
- いいね未済の状態で取消しようとすると 404 Not Found を返す
- いいね数・liked フラグは `PostResponse` に含まれるため、いいね API 自体はボディを返さない
