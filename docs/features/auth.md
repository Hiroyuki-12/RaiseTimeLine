# 機能定義：ログイン・ユーザー登録（F-01）

## 概要

メールアドレスとパスワードによるユーザー認証を提供する。
認証後はJWTトークンを発行し、以降のAPI呼び出しに使用する。

---

## ユーザー登録

### 入力項目

| 項目 | 型 | 必須 | バリデーション |
|------|---|------|---------------|
| ユーザー名 | 文字列 | ○ | 1〜50文字、英数字・アンダースコア・ハイフンのみ、重複不可 |
| メールアドレス | 文字列 | ○ | メール形式、重複不可 |
| パスワード | 文字列 | ○ | 8文字以上、英数字混在 |
| パスワード（確認） | 文字列 | ○ | パスワードと一致すること |

### 処理フロー

1. ユーザーが登録フォームに入力・送信
2. フロントエンドでバリデーション実行
3. バックエンドAPIへリクエスト送信
4. メールアドレス・ユーザー名の重複チェック（重複あり → 400エラー）
5. パスワードをハッシュ化（BCrypt）して `users` テーブルへ保存
6. JWTトークンを生成してレスポンスで返却
7. フロントエンドはトークンをローカルストレージに保存し、タイムライン画面へ遷移

### エラーケース

| ケース | レスポンス |
|--------|-----------|
| メールアドレス重複 | 400 Bad Request |
| ユーザー名重複 | 400 Bad Request |
| バリデーション違反 | 400 Bad Request |

---

## ログイン

### 入力項目

| 項目 | 型 | 必須 | バリデーション |
|------|---|------|---------------|
| メールアドレス | 文字列 | ○ | メール形式 |
| パスワード | 文字列 | ○ | 入力必須 |

### 処理フロー

1. ユーザーがログインフォームに入力・送信
2. バックエンドAPIへリクエスト送信
3. メールアドレスで `users` テーブルを検索（存在しない → 401エラー）
4. 入力パスワードとハッシュを照合（不一致 → 401エラー）
5. JWTトークンを生成してレスポンスで返却
6. フロントエンドはトークンをローカルストレージに保存し、タイムライン画面へ遷移

### エラーケース

| ケース | レスポンス |
|--------|-----------|
| メールアドレスが存在しない | 401 Unauthorized |
| パスワード不一致 | 401 Unauthorized |

---

## ログアウト

- フロントエンドのローカルストレージからJWTトークンを削除する
- バックエンドへのAPIコールは行わない（ステートレス認証のため）
- ログアウト後はログイン画面へ遷移する

---

## JWT トークン管理

| 項目 | 内容 |
|------|------|
| 保存場所 | ローカルストレージ |
| 有効期限 | 24時間 |
| リクエスト方法 | `Authorization: Bearer <token>` ヘッダーに付与 |
| 期限切れ時の動作 | ログイン画面へリダイレクト |
